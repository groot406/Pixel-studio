# Architecture and compatibility

## Choice of stack

Keep the supplied native ES modules and CSS. The canvas editor's drawing and animation behavior already exists independently of a component framework. A Vue/Tailwind conversion would replace working DOM/rendering code and visual rules without providing a necessary capability for this setup. There is no transpilation, runtime dependency, package download, or CSS reset. `jsconfig.json` provides editor module resolution; it is not a TypeScript type-check gate. New request options use JSDoc contracts.

Vue and TypeScript remain possible future migrations, but should be introduced around measured needs and protected by these behavior tests. Do not convert pixel data or file formats solely to match a UI framework.

## Ownership

- `domain/project.js` owns the canonical project schema, palette/layer validation, and compositing. `domain/limits.js` defines allocation limits; `geometry.js` supplies the same integer drawing algorithms to tools and retained artwork.
- `domain/artwork.js` owns retained operations, part validation, rendering, and local pixel overrides. `domain/parts.js` owns extraction, placement, forking, shared painting, and flattening. Neither depends on the DOM or file grammar.
- `domain/objects.js` exposes pixel runs and part instances as editable objects, optional group containers, scoped ordering/movement, and hit testing. It adapts the established cel/source contract rather than keeping a second scene schema. Object and group lock checks live in these use cases, including shared-definition references.
- `formats/` translates the project to/from external files and validates those inputs. `pxa.js` owns the 64-character pixel alphabet used by inpainting too.
- Image exports are pure and DOM-free so they run under `node --test`: `formats/image-export.js` selects frames, rasterises palette indices to RGBA at integer scales, lays out sheets and writes the Aseprite, Godot, TexturePacker/Unity and generic metadata; `export-bundle.js` plans, renders and encodes an export into files (zipping several). The encoders are dependency-free: `zip.js` (store-only ZIP and the shared CRC-32), `png.js` (PNG and APNG via `CompressionStream('deflate')`, with a stored-zlib fallback) and `gif.js` (GIF89a with LZW). `editor/export-dialog.js` owns the image tabs of the Export dialog, their preview and remembered settings; only still WebP uses the browser's canvas encoder.
- `storage/workspace.js` owns IndexedDB transactions and the non-durable fallback. The editor owns save ordering, document revisions, tab selection, and history.
- `features/ai/edit.js` protects structure and locked artwork during existing PXA edits. `patch-engine.js` owns rectangular masks, target confinement, fingerprints, sparse pixel patches, and palette-only proposals.
- `features/ai/composition-edit.js` owns scoped PXA 2 patch policy and validates every shared-part reference before allowing definition changes. It reuses the file codec's command parsing and the domain validator; scope policy stays out of the generic codec.
- `features/ai/requests.js` coordinates editing modes and returns one proposal contract. `response-contract.js` owns instruction limits and completion markers; `comparison.js` owns change summaries. `refinement.js` builds a single optional follow-up request and bounded visual previews. No validators import the dialog.
- `features/ai/edit-dialog.js` owns review UI and its lifecycle. `local-client.js` consumes completed NDJSON responses; partial output never becomes a proposal.
- `editor/app.js` remains the composition point for editor state and its existing DOM rendering. It alone commits proposals through the existing `mutate`/history path after checking tab ID, document revision, and source snapshot.
- `editor/panel-layout.js` owns resizable sidebars/timeline (CSS vars `--tools-size`, `--details-size`, `--timeline-size` on `#workbench`), the minimised Frames panel and floating panel sections (moved into a `.floating-panel`, with a hidden placeholder to dock back). `sanitizeLayout` validates the `pixel-studio.layout.v1` localStorage entry; floating panels dock automatically at ≤760px.
- `editor/part-library.js` renders the sidebar Parts strip (HTML5 drag with `PART_DRAG_TYPE`, dropped on `#canvas-stage`) and the library window. `domain/parts.js` adds `partUsage`, `frameRanges`, `renamePart`, `removePart` and `placePartInFrames` (one instance id across frames, so it is one object in the Objects panel).
- The canvas-toolbar Edit switch (`renderEditScope`/`setEditScope` in app.js) drives `state.objectScope` (animation/frame), or the in-place session scope (shared/frame) while editing an object; `.scope-frame` on `#workbench` marks single-frame editing.
- `editor/objects-panel.js` renders object selection and actions. `shared-part-editor.js` owns a detached, part-sized paint buffer, local history and full-sprite context previews. Applying shared artwork goes through the editor's one Undo boundary; Cancel discards its draft.
- Maths tools UI (all wired from `app.js` through one `mathsDeps` object; styles in `editor/maths-tools.css`):
  - `editor/tool-extras.js` – Gradient tool (drag preview, `applyGradient` on finish), pixel-perfect/clean-line point helpers, tile mode (wrapped drawing, 3×3 ghost, seam ticks via `tileSeams`, *Offset ½*) and the canvas overlay.
  - `editor/object-pose.js` – the Transform panel's *Object pose* block (pivot, skew, 3D turn, deform, sampling Nearest/RotSprite/Smooth AA via `setObjectEffects`; live preview on input, one undo step on change) and the draggable pivot marker.
  - `editor/animate-panel.js` – the Animate section: launchers for motion modes and the wave and 3D spin dialogs (with a live preview).
  - `editor/motion-modes.js` – direct-manipulation motion modes (move/tween, bounce, follow-through, IK, smear) with the floating `#motion-bar`. It owns a capture-phase pointer route on the canvas stage while active, draws ghosts/handles via `drawMotionOverlay` and recomputes a candidate project shown by the Live Preview through `state.previewOverride` (`previewAnimation()` in `app.js`). Apply commits through `mutate` as one undo step.
  - `editor/rig-mode.js` – Skeleton mode (`#rig-bar`, the same floating bar styles plus `editor/rig.css`): a Rig step that attaches bones by click-click or drag-and-drop and lists/renames/limits them, and a Pose step whose drags call the domain FK/IK/move functions on the snapshot taken at pointer down (one `remember` per drag). It forces the *This frame* edit scope while open, previews in-betweens through `state.previewOverride`, and closes during in-place edits; opening it closes any motion mode and vice versa.
  - `editor/rig-library.js` – the Pose step's pose library cards (thumbnails from `applyPose` on the animation's first frame, cropped to the character) and the *Templates…* and *Retarget…* dialogs (animated candidate preview, role and bone mapping selects); it keeps the last *Copy animation poses* clip in module state (and as JSON on the system clipboard) so it crosses project tabs.
  - `editor/curve-tool.js` – the Curve tool (P): the pending curve/path lives in module state and is drawn on the canvas overlay (`drawCurveOverlay`, via tool-extras), with pointer and key hooks called from `app.js` before the generic tool handling. Applying builds one `state.drawing` stroke through `drawPoints` (brush, mirror), clips it to the selection, optionally runs `antialiasStroke` and ends with `finishDrawing` (one undo step, *All frames* repeat); in-place edits replay it as one pencil stroke.
  - `editor/effects-panel.js` – the Effects section; each dialog renders a before/after preview with `applyPixelEffect` and applies it in the Edit scope, limited by the selection.
  - `editor/cleanup-panel.js` – *Pixel cleanup*: runs `cleanup.findIssues` on the active cel (re-run when its pixels change), lists issues under the Effects buttons, draws markers via `drawCleanupOverlay` and applies fixes as the `pixelFix` effect through `mutate`.
  - `editor/palette-tools.js` – *Shading ramp* and *Colour cycle* dialogs in the palette panel.
  - `editor/palette-studio.js` – *Palette studio* dialog (harmonies wheel, shades & tints, presets, analysis) and the palette swatch context menu; it applies changes through `mutate` so each is one undo step.
- `domain/object-clipboard.js` copies an instance, group or pixel object (with per-frame poses and used palette colors) and pastes it into any animation or project, remapping colors and reusing identical parts. `domain/objects.js#dropObject` implements panel drag and drop. `domain/parts.js#growPart` pads a part and shifts every referencing instance so artwork stays put; `features/objects/in-place-edit.js` uses it to grow a part while painting outside it and offers part-space pixel selection.
- `domain/object-create.js` turns a rectangle or mask of layer pixels into a reusable part plus instances (`createObjectFromPixels`, one shared part across identical frames), and splits a layer into one object per connected island (`pixelIslands`, `splitIntoObjects`). `domain/toolbox.js` holds the pure helpers behind the dither, shade, pixel-perfect and magic-wand tools (`ditherCell`, `shadeIndex`, `pixelPerfectStep`, `connectedRegion`, `findIslands`); `domain/selection.js#maskBounds`/`moveMaskedPixels` support non-rectangular selections.
- `domain/resize.js` holds the resize-handle maths (`resizeBox`, `keepAreaSide`). A `use` op may carry `width`/`height` (display size in part orientation, before the transform). `geometry.js#instanceSize`/`sampleIndex` map displayed pixels to part pixels with `floor((2i+1)·src/(2·tgt))`, which rendering, hit-testing and `objectBounds` share; `objects.js#resizeObject` applies a box to the current frame or every frame using the same part. In PXA 2 this is the `RESIZE instance-id width height` cel command. `toolbox.js#repeatPixelChanges` replays one stroke's changed pixels onto the other frames when *Edit in* is *All frames*.
- Transforms are the 8-element dihedral group (`N FX FY R90 R180 R270 R90FX R270FX`, see `TRANSFORM_MATRICES`/`composeTransform` in `domain/geometry.js`); quarter turns and flips are lossless. A `use` op may also carry a whole-degree `angle` (−179..180, PXA cel command `ROTATE id degrees`) applied after the transform about the pivot (`geometry.js#instancePivot`: the centre of the optional `pivot` pixel in the turned, unrotated box, else the exact box centre). Optional `skew {x,y}`, `tilt {x,y,perspective?}` (pseudo-3D turn about the horizontal/vertical axes through the pivot: a plane projective map, see `geometry.js#tiltMap`; perspective in percent, default 30), `deform {kind:'wave'|'bulge'|'twist',…}` and `sampling:'rotsprite'|'aa'` (`domain/rotsprite.js`; `aa` supersamples 4×4 and blends via `antialias.paletteBlend`) follow the order resize → transform → deform → skew → 3D turn → rotation; `objects.js#setObjectEffects` edits them (`tiltObjects` adds to the 3D turn for the Transform tool's diamond handle) and PXA 2 stores them as `PIVOT`/`SKEW`/`TILT`/`DEFORM`/`SAMPLE`. Rendering and hit-testing inverse-map each pixel of `instanceBox` through `canvasToPartPoint` (nearest neighbour), so the part is never modified. Resampling poses (free angle, skew, tilt, deform or resize) go through `geometry.js#instanceImage` (cached per part image and pose), which also repairs gaps: dropped source pixels linked to a same-colour neighbour are re-placed at their forward-mapped position (`partToInstancePoint`) and same-colour 8-neighbours whose images no longer touch are bridged, so 1px lines stay 8-connected and outlines closed (`tests/resample-gaps.test.mjs`); neutral poses keep the exact direct path. `renderParts(parts, palette)` gives Smooth AA the palette, and `renderOperations` blends its partly covered silhouette pixels with the cel pixel beneath. `turnObjects`/`rotateObjects` keep the box centre fixed. In-place editing (`features/objects/in-place-edit.js`) of a rotated/resized instance draws through an *editing pose* (no angle, own size, same centre); the stored op is untouched and `growPart`/`grownInstance` keep it in place when the part grows. `previewInPlaceEdit(session, true)` renders the placed pose. In “this frame only” scope the draft is instead the instance rendered as drawn (`inPlaceMode` = `baked`); applying gives that placement its own part (forked if shared) with transform `N` and no angle/size.
- Multi-object operations (`orderObjects`, `translateObjects`, `deleteObjects` in `domain/objects.js`; `copyObjects` in `domain/object-clipboard.js`) take `[{layerId,key}]` lists. Several items copy to a `kind:'multi'` clip, which `pasteObject` pastes item by item and returns as `items`. The editor keeps the primary item in `objectSelection` and the rest in `objectMulti`.
- `domain/motion.js` holds pure animation maths (easing, `tweenPose`, squash/stretch, paths, springs, two-bone IK, smears) on flat poses; `poseOf`/`applyPose` are the only conversion between a `use` op and a pose (`x y width height angle skewX skewY tiltX tiltY phase bulge twist`; tilts tween linearly so 0 → 360 is a full spin), and `pivotWorld` delegates to `geometry.instancePivot`. `domain/animate.js` applies that maths to a project (`tweenObject`, `autoSquashStretch`, `springFollow`, `ikLimb`, `waveAnimate`, `spin3d`, `smearFrame`, plus `tweenToPose`, `bounceInPlace`, `setPivotAt` and `limbJoints` for the motion modes; `springFollow` also has a pivot `swing` mode and `smearFrame` with an `instanceId` smears only that object), addressing one instance id across frames of one animation and inserting frames as `makeLayeredFrame` copies.
- `domain/skeleton.js` holds the rig: `project.bones` (version 3) is a forest of `{id, name, layerId, instanceId, parent, anchor, limit, rest}` where each bone is one placed instance (the same instance id in every frame), its joint is the instance's pivot and `anchor` is where that joint sits in the parent's part space (so it travels with the parent's transform). `validateProject` (`readBones`) prunes bones whose instance or parent is gone and breaks cycles. A frame's pose is just its instances: `relPose` reads relative angles, `layoutFrame` writes absolute angles top-down and moves each child so its pivot lands on its parent's anchor, always from the frame's current state so repeated edits do not drift. On top: `attachBone`, `rotateBone` (FK), `moveSkeleton`, `ikChain` (CCD `solveChain` in `motion.js`, with limits), `copyPose`/`pastePose`/`mirrorPose`/`resetPose`/`setRestPose` and `tweenPoses` (key poses → in-betweens, shortest-arc angles, eased root path). `objects.js` and `animate.js` re-lay out descendants when a rigged part is moved, rotated or tweened, and PXA 2 stores the rig as `BONE` lines.
- `domain/poses.js` makes rigs reusable: `project.poses` (validated by `readPoses`: known bones only, root moves) with `savePose`/`applyPose` (blend `amount`, `mirror` via `sidePairs`, root `move`)/`renamePose`/`deletePose`; `detectRoles` finds humanoid roles in a `rigDescriptor` by name tokens (`nameRole`, aliases such as `ArmL`, `upper_arm_l`, `LeftForeArm`) and then by shape (chain depth, joint position, facing); `matchBones` pairs two rigs (role → name → kind+side → Dice similarity → tree position); a pose clip (`copyAnimationPoses`, format `pixel-studio-poses`) holds a character's per-frame relative angles and root moves, and `retargetAnimation` writes them onto another rig as rest-pose deltas with root motion scaled by leg length. `writePoseFrames` (shared) lays out new/replaced/merged frames and grounds the figure on its lowest drawn pixel.
- `domain/templates.js`: `templatePose(id, t)` is a pure loop function (t ∈ [0, 1], t = 0 equals t = 1) giving per-role angle changes and a lift for walk, run, jump (eased key poses), idle, wave and hover; `generateTemplate` samples it per frame and writes the frames with `writePoseFrames`.
- `domain/pixel-fx.js` (distance-field outlines/glow/shading, dithering, gradients, line cleanup, smears, wrap/tiles) and `domain/colour.js` (OKLab/OKLCH, ramps, colour cycling), `domain/palette-theory.js` (harmonies, tints/shades, ΔE similarity, value gaps, merge, and whole-project `replacePalette`/`removePaletteColour`/`reorderPalette`, which remap raster pixels, retained ops/overrides and parts) and `domain/palette-presets.js` (curated preset data) work on plain pixel arrays and palettes. `domain/curves.js` samples cubic Béziers and centripetal Catmull-Rom paths and rasterises them pixel-perfect (`curvePixels`, `pathPixels`, `polygonFill`, handle helpers). `domain/shading.js` detects palette ramps (`paletteRamp`: hue-shifted OKLab chains or lightness-only), steps colours along them (`shadeStep`/`shadeMap`, used by the Shade tool) and builds `autoOutline` (selective ramp-darkened or single colour). `domain/cleanup.js` finds strays, doubled corners, jaggies and banding (`findIssues`) with safe fixes (`safeFixes`, `applyFixes`). `domain/antialias.js` is palette-aware pixel-art AA: `paletteBlend` (nearest OKLab palette colour meaningfully between two), `antialiasStroke` (AA pixels at the stair steps of a 1px stroke, used by the Line/Ellipse/Curve *Anti-alias* option) and `smoothJaggies` (the *Smooth jaggies* effect). `domain/effects.js` applies them to cels through `artwork.writeCelPixels` (raster pixels or local overrides, skipping locked-object cels like the paint tools) and holds the pure tool helpers `strokePoints`/`toolLinePoints` (pixel-perfect, clean slopes, wrap-around).
- `local/` owns loopback HTTP, CSRF/origin checks, cancellation, and Codex process lifecycle. `codex-runtime.mjs` prefers the installed ChatGPT desktop runtime on macOS, falling back to the CLI on PATH. The model catalog and model validation use that same runtime; no model IDs are synthesized. `pixel-request.mjs` declares supported request formats and text/image limits. For visual refinement, the bridge writes validated inline PNGs to its own temporary paths and cleans them up with the session. Browser input cannot supply filesystem paths, commands, credentials, or arbitrary provider URLs.

## Project contract

Raster projects retain version 2 with `format: 'pixel-studio'`, `name`, `width`, `height`, `palette`, `layers`, and `animations`. Version 3 adds a flat `parts` library and optional cel `source: {ops, overrides}`. Each layer has `id`, `name`, `visible`, and `locked`. Each animation has `id`, `name`, `fps`, and `frames`, plus optional `layerOrder`: every shared layer ID exactly once, bottom to top. Without it, declaration order applies, preserving existing projects. Each frame has `id`, `duration` in milliseconds, and one cel for every layer.

The editor presents Objects instead of Layers. The existing `layers` and `cels` fields remain the compatibility storage contract. Containers with optional `group: false` expose their objects directly; `true` displays a group. Omitted `group` displays legacy layers as groups, preserving their names, flags, isolated erasures, overrides, IDs and artwork. New projects begin with ungrouped pixels. Groups are one level deep and can be added or ungrouped without baking their artwork. Instances can move between containers. Pixel drawing runs retain their original order, and final local overrides stay above their container's operations.

Part instances optionally carry a `name` and boolean `visible`/`locked` settings. Metadata is normalized together when present. A hidden instance remains in its source; a locked instance prevents moving, reordering, deleting or editing its definition. Shared definition edits check all references, including hidden instances and other animations. Pixel AI edits conservatively protect a whole cel containing a locked instance. Canvas Object mode hit-tests the visible result, including transformations, transparent part pixels, local erasures and hidden groups. Animation movement preserves each frame's existing position by adding the same offset, rather than replacing every pose with one position.

Object edits default to the current animation and can target one frame. Containers use animation `layerOrder` or an optional frame `layerOrder` override, with the same complete-permutation invariant. Copying a frame copies its explicit order; codec `PREV`/`FROM` commands copy cels only. Adding and deleting containers updates both order levels. Optional grouping and per-instance metadata persist in native JSON and PXA 2 (`STACK` and `INSTANCE`); PXA 1 and PXS remain raster exports and bake individual object settings/grouping into each container's pixels. They preserve the rendered result, timing and stack order, while PXA 2 preserves shared editability.

Layer definitions, visibility and locks remain shared. The editor's container order controls default to the active animation and can override one frame. The domain compositor resolves the owning animation for each frame, so canvas, onion skin, thumbnails, playback, AI comparisons and PNG/spritesheet exports use the same stack. Adding/duplicating a layer inserts it above the selected layer in each animation's own stack; deleting it removes its references everywhere. Duplicate/mirrored animations retain their source order, as do new animations started from a copied frame. A project-wide merge requires the same adjacent pair, in the same direction, across all animations; otherwise it would change other animations' appearance.

PXA 1/2 support an optional `ORDER` command once after `ANIM`, before its first `FRAME`. PXA 1 lists layer declaration indices; PXA 2 lists stable layer IDs. `FRAME FROM` copies only cels, retaining the receiving animation's order. Legacy text without `ORDER` remains supported; readers without this extension reject new ORDER files. PXS keeps container version 1 and the original raster payload schema 2 for projects without explicit animation orders. Payload schema 3 adds one u8 declaration index per layer after each animation's frame count; cel bytes remain in declaration order. This binary payload version is separate from native JSON schema 3's reusable artwork support. New payloads require an updated reader. PXA 2 is still the format that retains reusable parts.

PXA 1/2 `FRAMEORDER` follows `FRAME`, before any cel data, and overrides only that frame's stack. PXS payload schema 4 retains schema 3's animation order and adds one u8 layer declaration index per layer after each frame duration. It is emitted only when a frame has an explicit order; schema 2/3 files remain readable and are still written when sufficient. Width/height and container header fields do not change.

Pixels are ordinary arrays of palette indices; `-1` is transparent. A cel is bound by `layerId`, never by an assumed array position. In retained cels, source is authoritative: validation rebuilds the pixels rather than trusting a stored cache. The editor's transaction boundary turns legacy drawing-buffer changes into sparse local overrides before validation and history. Shared-definition changes bypass that adapter so they do not become local overrides. Resize explicitly bakes affected cels.

Frame/animation IDs and timing survive AI edits. PXA 2 preserves stable IDs; older imports can regenerate them. Compatibility tests compare artwork independently of IDs, while PXA 2 tests also require source and identity round trips. PXA 1/PXS exports bake references without changing rendered layers or frame timing. See [PXA 2](pxa-v2.md) for the grammar, limits, migration decisions, and measured tradeoffs.

## Supplied patch adaptation

The original ZIP is retained in `patches/`; its original instructions are in `docs/upstream/inpaint-patch.md`. The integrated engine uses the existing project schema directly. A second normalized schema, duplicate project validator, and second compositor would add unnecessary conversion and competing invariants.

Changes from the standalone patch:

- Use the existing 64-slot PXA alphabet, including lowercase letters, `@`, and `$`.
- Accept the editor's fractional FPS, full instruction length, cel identities, canvas limits, and pixel budget.
- Include project/entity identities, frame counts, and fractional FPS in fingerprints. Fingerprints are stale-response checks, not cryptographic authentication.
- Require the existing unique completion comment for both patch modes, so a valid prefix of an interrupted patch cannot be applied.
- Add selected layer/rectangle context and revision checking to the existing Apply callback.
- Teach both HTTP validation and the Codex base instructions about `PXAINPAINT 1` and `PXAPALETTE 1`; retaining PXA-only instructions would make local recoloring fail.
- Keep the original canvas maximum of 128 and PXS u8 dimension fields. Increasing the canvas to 256 is a separate format/version migration, not just a constant change.

Recoloring intentionally affects the appearance of locked layers because colors are shared. It does not change their indexed pixels. The UI explains that distinction before generation and lists every changed swatch during review.

## Build and runtime

`public/` is copied to `dist/`, then `src/` to `dist/src/`. The local service serves only that build directory and rejects paths escaping it. `npm start` builds automatically. `npm run dev` watches browser inputs and rebuilds them in order; Node's watcher restarts the service for server changes. The browser is refreshed manually.

Do not edit generated files. Source files contain no credentials. No remote repository, hosted Site, publication, or deployment is configured by this local setup.

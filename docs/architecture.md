# Architecture and compatibility

## Choice of stack

Keep the supplied native ES modules and CSS. The canvas editor's drawing and animation behavior already exists independently of a component framework. A Vue/Tailwind conversion would replace working DOM/rendering code and visual rules without providing a necessary capability for this setup. There is no transpilation, runtime dependency, package download, or CSS reset. `jsconfig.json` provides editor module resolution; it is not a TypeScript type-check gate. New request options use JSDoc contracts.

Vue and TypeScript remain possible future migrations, but should be introduced around measured needs and protected by these behavior tests. Do not convert pixel data or file formats solely to match a UI framework.

## Ownership

- `domain/project.js` owns the canonical project schema, palette/layer validation, and compositing. `domain/limits.js` defines allocation limits; `geometry.js` supplies the same integer drawing algorithms to tools and retained artwork.
- `domain/artwork.js` owns retained operations, part validation, rendering, and local pixel overrides. `domain/parts.js` owns extraction, placement, forking, shared painting, and flattening. Neither depends on the DOM or file grammar.
- `domain/objects.js` exposes pixel runs and part instances as editable objects, optional group containers, scoped ordering/movement, and hit testing. It adapts the established cel/source contract rather than keeping a second scene schema. Object and group lock checks live in these use cases, including shared-definition references.
- `formats/` translates the project to/from external files and validates those inputs. `pxa.js` owns the 64-character pixel alphabet used by inpainting too.
- Image exports are pure and DOM-free so they run under `node --test`: `formats/image-export.js` selects frames, rasterises palette indices to RGBA at integer scales, lays out sheets and writes the Aseprite, Godot, TexturePacker/Unity and generic metadata; `export-bundle.js` plans, renders and encodes an export into files (zipping several). The encoders are dependency-free: `zip.js` (store-only ZIP and the shared CRC-32), `png.js` (PNG and APNG via `CompressionStream('deflate')`, with a stored-zlib fallback) and `gif.js` (GIF89a with LZW). `editor/export-dialog.js` owns the image tabs of the Export dialog, their preview and remembered settings; only still WebP uses the browser's canvas encoder.
- `storage/workspace.js` owns IndexedDB transactions and the non-durable fallback (`memoryStore`, same API, used by tests). The editor owns save ordering, document revisions, tab selection, and history.
- `domain/history.js` (undo structural sharing), `domain/versions.js` (version metadata, retention thinning, recovery-journal selection and the lossless `packProject` format) are pure; `editor/safety.js` owns recovery journals, heartbeats, the recovery banner and the global error toast; `editor/versions-dialog.js` owns automatic/named snapshots and the Version history dialog. See *Persistence, history and performance* below.

In PXA 2 this is the `RESIZE instance-id width height` cel command. `toolbox.js#repeatPixelChanges` replays one stroke's changed pixels onto the other frames when *Edit in* is *All frames*.
- Transforms are the 8-element dihedral group (`N FX FY R90 R180 R270 R90FX R270FX`, see `TRANSFORM_MATRICES`/`composeTransform` in `domain/geometry.js`); quarter turns and flips are lossless. A `use` op may also carry a whole-degree `angle` (−179..180, PXA cel command `ROTATE id degrees`) applied after the transform about the pivot (`geometry.js#instancePivot`: the centre of the optional `pivot` pixel in the turned, unrotated box, else the exact box centre). Optional `skew {x,y}`, `tilt {x,y,perspective?}` (pseudo-3D turn about the horizontal/vertical axes through the pivot: a plane projective map, see `geometry.js#tiltMap`; perspective in percent, default 30), `deform {kind:'wave'|'bulge'|'twist',…}` and `sampling:'rotsprite'|'aa'` (`domain/rotsprite.js`; `aa` supersamples 4×4 and blends via `antialias.paletteBlend`) follow the order resize → transform → deform → skew → 3D turn → rotation; `objects.js#setObjectEffects` edits them (`tiltObjects` adds to the 3D turn for the Transform tool's diamond handle) and PXA 2 stores them as `PIVOT`/`SKEW`/`TILT`/`DEFORM`/`SAMPLE`. Rendering and hit-testing inverse-map each pixel of `instanceBox` through `canvasToPartPoint` (nearest neighbour), so the part is never modified. Resampling poses (free angle, skew, tilt, deform or resize) go through `geometry.js#instanceImage` (cached per part image and pose), which also repairs gaps: dropped source pixels linked to a same-colour neighbour are re-placed at their forward-mapped position (`partToInstancePoint`) and same-colour 8-neighbours whose images no longer touch are bridged, so 1px lines stay 8-connected and outlines closed (`tests/resample-gaps.test.mjs`); neutral poses keep the exact direct path. Exactly edge-on tilts (|cos x·cos y| ≈ 0, `geometry.js#edgeOn`) render a 1px sliver by z-buffering forward-mapped part samples (nearest-to-viewer pixel wins, `sliverPixels`); a near-edge-on tilt whose inverse map finds no pixels snaps to the edge-on angle, so a spin never blinks out. `renderParts(parts, palette)` gives Smooth AA the palette, and `renderOperations` blends its partly covered silhouette pixels with the cel pixel beneath. `turnObjects`/`rotateObjects` keep the box centre fixed. In-place editing (`features/objects/in-place-edit.js`) of a rotated/resized instance draws through an *editing pose* (no angle, own size, same centre); the stored op is untouched and `growPart`/`grownInstance` keep it in place when the part grows. `previewInPlaceEdit(session, true)` renders the placed pose. In “this frame only” scope the draft is instead the instance rendered as drawn (`inPlaceMode` = `baked`); applying gives that placement its own part (forked if shared) with transform `N` and no angle/size.
- Multi-object operations (`orderObjects`, `translateObjects`, `deleteObjects` in `domain/objects.js`; `copyObjects` in `domain/object-clipboard.js`) take `[{layerId,key}]` lists. Several items copy to a `kind:'multi'` clip, which `pasteObject` pastes item by item and returns as `items`. The editor keeps the primary item in `objectSelection` and the rest in `objectMulti`.
- `domain/motion.js` holds pure animation maths (easing, `tweenPose`, squash/stretch, paths, springs, two-bone IK, smears) on flat poses; `poseOf`/`applyPose` are the only conversion between a `use` op and a pose (`x y width height angle skewX skewY tiltX tiltY phase bulge twist`; tilts tween linearly so 0 → 360 is a full spin), and `pivotWorld` delegates to `geometry.instancePivot`. `domain/animate.js` applies that maths to a project (`tweenObject`, `autoSquashStretch`, `springFollow`, `ikLimb`, `waveAnimate`, `spin3d` (optional per-frame `duration`, else the from-frame's), `smearFrame`, plus `tweenToPose`, `bounceInPlace`, `setPivotAt` and `limbJoints` for the motion modes; `springFollow` also has a pivot `swing` mode and `smearFrame` with an `instanceId` smears only that object), addressing one instance id across frames of one animation and inserting frames as `makeLayeredFrame` copies.
- `domain/skeleton.js` holds the rig: `project.bones` (version 3) is a forest of `{id, name, layerId, instanceId, parent, anchor, limit, rest}` where each bone is one placed instance (the same instance id in every frame), its joint is the instance's pivot (drawn position `jointWorld`, which follows skew, tilt and deform via `boxToWorld`/`geometry.deformPoint`) and `anchor` is where that joint sits in the parent's part space (so it travels with the parent's transform). `validateProject` (`readBones`) prunes bones whose instance or parent is gone and breaks cycles. A frame's pose is just its instances: `relPose` reads relative angles, `layoutFrame` writes absolute angles top-down and moves each child so its drawn joint lands on its parent's anchor, always from the frame's current state so repeated edits do not drift. On top: `attachBone`, `rotateBone` (FK), `moveSkeleton`, `ikChain` (CCD `solveChain` in `motion.js`, with limits), `copyPose`/`pastePose`/`mirrorPose`/`resetPose`/`setRestPose` and `tweenPoses` (key poses → in-betweens, shortest-arc angles, eased root path). `objects.js` and `animate.js` re-lay out descendants when a rigged part is moved, rotated or tweened, and PXA 2 stores the rig as `BONE` lines.
- `domain/poses.js` makes rigs reusable: `project.poses` (validated by `readPoses`: known bones only, root moves) with `savePose`/`applyPose` (`rootBoneId` maps the pose onto a copied character by name via `poseForCharacter`, blend `amount`, `mirror` via `sidePairs`, root `move`)/`renamePose`/`deletePose`; `detectRoles` finds humanoid roles in a `rigDescriptor` by name tokens (`nameRole`, aliases such as `ArmL`, `upper_arm_l`, `LeftForeArm`) and then by shape (chain depth, joint position, facing); `matchBones` pairs two rigs (role → name → kind+side → Dice similarity → tree position); a pose clip (`copyAnimationPoses`, format `pixel-studio-poses`) holds a character's per-frame relative angles and root moves, and `retargetAnimation` writes them onto another rig as rest-pose deltas with root motion scaled by leg length. `writePoseFrames` (shared) lays out new/replaced/merged frames and grounds the figure on its lowest drawn pixel.
- `domain/motion-intent.js` runs a JSON **motion plan** (`{steps:[{op, target, frames, times, speed, easing, …}]}`, ops in `MOTION_OPS`). `normalizePlan` validates and clamps it with readable errors. `motionTargets`/`resolveTarget` list and fuzzily resolve objects, parts, bones, roles (`nameRole`) and pronouns. `runMotionPlan` runs the steps in order on a copy of the project, as a new animation, appended or replacing the current one, by calling `generateTemplate`, `applyPose`, `rotateBone`/`ikChain`/`tweenPoses`, `tweenToPose`, `bounceInPlace`, `spin3d`, `springFollow`, `autoSquashStretch` and `waveAnimate`. It returns `{project, animationId, frameIds, summary, warnings}`. Errors name the step; objects without a rig fall back to simpler motions with a warning. `domain/motion-phrases.js` (`parseMotionText`) is the offline, rule-based English parser that turns counts, frames, speed and size words, directions, targets and verbs into a plan, and reports clauses it cannot read.
- `domain/templates.js`: `templatePose(id, t)` is a pure loop function (t ∈ [0, 1], t = 0 equals t = 1) giving per-role angle changes and a lift for walk, run, jump (eased key poses), idle, wave and hover; `generateTemplate` samples it per frame and writes the frames with `writePoseFrames`.
- `domain/pixel-fx.js` (distance-field outlines/glow/shading, dithering, gradients, line cleanup, smears, wrap/tiles) and `domain/colour.js` (OKLab/OKLCH, ramps, colour cycling), `domain/palette-theory.js` (harmonies, tints/shades, ΔE similarity, value gaps, merge, and whole-project `replacePalette`/`removePaletteColour`/`reorderPalette`, which remap raster pixels, retained ops/overrides and parts) and `domain/palette-presets.js` (curated preset data) work on plain pixel arrays and palettes. `domain/curves.js` samples cubic Béziers and centripetal Catmull-Rom paths and rasterises them pixel-perfect (`curvePixels`, `pathPixels`, `polygonFill`, handle helpers). `domain/shading.js` detects palette ramps (`paletteRamp`: hue-shifted OKLab chains or lightness-only), steps colours along them (`shadeStep`/`shadeMap`, used by the Shade tool) and builds `autoOutline` (selective ramp-darkened or single colour). `domain/cleanup.js` finds strays, doubled corners, jaggies and banding (`findIssues`) with safe fixes (`safeFixes`, `applyFixes`). `domain/antialias.js` is palette-aware pixel-art AA: `paletteBlend` (nearest OKLab palette colour meaningfully between two), `antialiasStroke` (AA pixels at the stair steps of a 1px stroke, used by the Line/Ellipse/Curve *Anti-alias* option) and `smoothJaggies` (the *Smooth jaggies* effect). `domain/effects.js` applies them to cels through `artwork.writeCelPixels` (raster pixels or local overrides, skipping locked-object cels like the paint tools) and holds the pure tool helpers `strokePoints`/`toolLinePoints` (pixel-perfect, clean slopes, wrap-around).
- `local/` owns loopback HTTP, CSRF/origin checks, cancellation, and Codex process lifecycle. `codex-runtime.mjs` prefers the installed ChatGPT desktop runtime on macOS, falling back to the CLI on PATH. The model catalog and model validation use that same runtime; no model IDs are synthesized. `pixel-request.mjs` declares supported request formats and text/image limits. For visual refinement, the bridge writes validated inline PNGs to its own temporary paths and cleans them up with the session. Browser input cannot supply filesystem paths, commands, credentials, or arbitrary provider URLs.

## Project contract

Raster projects retain version 2 with `format: 'pixel-studio'`, `name`, `width`, `height`, `palette`, `layers`, and `animations`. Version 3 adds a flat `parts` library and optional cel `source: {ops, overrides}`. Each layer has `id`, `name`, `visible`, and `locked`. Each animation has `id`, `name`, `fps`, and `frames`, plus optional `layerOrder`: every shared layer ID exactly once, bottom to top. Without it, declaration order applies, preserving existing projects. Each frame has `id`, `duration` in milliseconds, and one cel for every layer.

The editor presents Objects instead of Layers. The existing `layers` and `cels` fields remain the compatibility storage contract. Containers with optional `group: false` expose their objects directly; `true` displays a group. Omitted `group` displays legacy layers as groups, preserving their names, flags, isolated erasures, overrides, IDs and artwork. New projects begin with ungrouped pixels. Groups are one level deep and can be added or ungrouped without baking their artwork. Instances can move between containers. Pixel drawing runs retain their original order, and final local overrides stay above their container's operations.

Part instances optionally carry a `name` and boolean `visible`/`locked` settings. Metadata is normalized together when present. A hidden instance remains in its source; a locked instance prevents moving, reordering, deleting or editing its definition. Shared definition edits check all references, including hidden instances and other animations. Pixel AI edits conservatively protect a whole cel containing a locked instance. Canvas Object mode hit-tests the visible result, including transformations, transparent part pixels, local erasures and hidden groups. Animation movement preserves each frame's existing position by adding the same offset, rather than replacing every pose with one position.

Object edits default to the current animation and can target one frame. Containers use animation `layerOrder` or an optional frame `layerOrder` override, with the same complete-permutation invariant. Copying a frame copies its explicit order; codec `PREV`/`FROM` commands copy cels only. Adding and deleting containers updates both order levels. Optional grouping and per-instance metadata persist in native JSON and PXA 2 (`STACK` and `INSTANCE`); PXA 1 and PXS remain raster exports and bake individual object settings/grouping into each container's pixels. They preserve the rendered result, timing and stack order, while PXA 2 preserves shared editability.

Layer definitions, visibility and locks remain shared. The editor's container order controls default to the active animation and can override one frame. The domain compositor resolves the owning animation for each frame, so canvas, onion skin, thumbnails, playback, AI comparisons and PNG/spritesheet exports use the same stack. Adding/duplicating a layer inserts it above the selected layer in each animation's own stack; deleting it removes its references everywhere. Duplicate/mirrored animations retain their source order, as do new animations started from a copied frame. A project-wide merge requires the same adjacent pair, in the same direction, across all animations; otherwise it would change other animations' appearance.

Frames may carry `kind` (`key`/`breakdown`/`inbetween`; `validateProject` drops anything else). PXA 1 and 2 write it as an optional last `FRAME` token (`KEY`/`BREAKDOWN`/`INBETWEEN`); older readers that require the exact token count reject such lines, and frames without a kind are written unchanged. PXS bakes frames and does not store kinds.

PXA 1/2 support an optional `ORDER` command once after `ANIM`, before its first `FRAME`. PXA 1 lists layer declaration indices; PXA 2 lists stable layer IDs. `FRAME FROM` copies only cels, retaining the receiving animation's order. Legacy text without `ORDER` remains supported; readers without this extension reject new ORDER files. PXS keeps container version 1 and the original raster payload schema 2 for projects without explicit animation orders. Payload schema 3 adds one u8 declaration index per layer after each animation's frame count; cel bytes remain in declaration order. This binary payload version is separate from native JSON schema 3's reusable artwork support. New payloads require an updated reader. PXA 2 is still the format that retains reusable parts.

PXA 1/2 `FRAMEORDER` follows `FRAME`, before any cel data, and overrides only that frame's stack. PXS payload schema 4 retains schema 3's animation order and adds one u8 layer declaration index per layer after each frame duration. It is emitted only when a frame has an explicit order; schema 2/3 files remain readable and are still written when sufficient. Width/height and container header fields do not change.

Pixels are ordinary arrays of palette indices; `-1` is transparent. A cel is bound by `layerId`, never by an assumed array position. In retained cels, source is authoritative: validation rebuilds the pixels rather than trusting a stored cache. The editor's transaction boundary turns legacy drawing-buffer changes into sparse local overrides before validation and history. Shared-definition changes bypass that adapter so they do not become local overrides. Resize explicitly bakes affected cels.

Frame/animation IDs and timing survive AI edits. PXA 2 preserves stable IDs; older imports can regenerate them. Compatibility tests compare artwork independently of IDs, while PXA 2 tests also require source and identity round trips. PXA 1/PXS exports bake references without changing rendered layers or frame timing. See [PXA 2](pxa-v2.md) for the grammar, limits, migration decisions, and measured tradeoffs.

## Supplied patch adaptation

The original ZIP is retained in `patches/`; its original instructions are in `docs/upstream/inpaint-patch.md`. The integrated engine uses the existing project schema directly. A second normalized schema, duplicate project validator, and second compositor would add unnecessary conversion and competing invariants.

Changes from the standalone patch:

- Use the existing 64-slot PXA alphabet, including lowercase letters, `@`, and `$`.
- Accept the editor's fractional FPS, full instruction length, cel identities, canvas limits, and pixel budget.
- Include project/entity identities, frame counts, and fractional FPS in fingerprints. Fingerprints are stale-response checks, not cryptographic authentication.
- Require the existing unique completion comment for both patch modes, so a valid prefix of an interrupted patch cannot be applied.
- Add selected layer/rectangle context and revision checking to the existing Apply callback.
- Teach both HTTP validation and the Codex base instructions about `PXAINPAINT 1` and `PXAPALETTE 1`; retaining PXA-only instructions would make local recoloring fail.
- The canvas maximum is 256 (`limits.js` `MAX_SIZE`, 4,194,304 stored pixels; pivots `PIVOT_MIN`..`PIVOT_MAX`). PXS keeps u8 dimension fields with 0 meaning 256 (older readers reject it) and an 8 MiB payload cap. 512 was not adopted: commit and journal costs scale with pixels (256: ~70 ms stroke commit, ~12 MB journal in `npm run bench`).

Recoloring intentionally affects the appearance of locked layers because colors are shared. It does not change their indexed pixels. The UI explains that distinction before generation and lists every changed swatch during review.

## Persistence, history and performance

**Saving.** `scheduleSave` bumps the document revision; `idleSave` waits until no stroke is in progress (and for `requestIdleCallback` where available) about 500 ms after the last change, and `persistDocument` writes a clone. Hiding or closing the page saves at once. IndexedDB (database version 2) keeps `projects`/`metadata` as before and adds `backups` (the previous record, written in the same transaction as the new one, so a save is atomic and `getDocument` falls back to the last good copy), `versions` + `versionData` (metadata and packed data, indexed by `documentId`) and `journal`. Errors thrown inside request callbacks abort the transaction and reject the save instead of escaping. A failed save marks the document `saveError` (header status *Not saved*), writes a journal, shows one warning (quota-specific for `QuotaExceededError`) and retries after 15 s.

**Recovery.** `safety.js` writes a journal (`localStorage` key `pixel-studio.journal.<documentId>`, falling back to the IndexedDB `journal` store with a one-time warning) for documents that have been dirty for 5 s, on `pagehide`/hidden, after failed saves and on uncaught errors; a successful save at the same revision removes it. Each tab refreshes a heartbeat in `pixel-studio.heartbeats` every 5 s and removes it on `pagehide`. On start, `orphanedJournals` keeps journals whose session has no fresh (15 s) heartbeat; those identical to the saved project are deleted silently, the rest are offered one at a time in the recovery banner. Restore goes through `mutate` (undoable); Discard stores the work as a version. Journals and versions use `packProject` (JSON with run-length-encoded integer arrays), which keeps every id; PXA 1 is not id-preserving for raster projects, so it is used only for downloads.

**Versions.** `versionMeta` records name, kind (`named`/`auto`/`before`), reason, counts, size and a first-frame thumbnail. `noteChange` feeds `trackActivity`; `snapshotDue` asks for an automatic snapshot after 5 active minutes (gaps over a minute do not count) or 100 changes, checked after each save. `versionBefore(reason)` snapshots before Replace palette, templates, Retarget, AI edits, PNG imports into the project and restoring a version. `thinVersions` keeps named versions, all autos from the last hour, the newest per hour for a day and per day for 30 days, then drops the oldest autos above 24 MB or 300 versions.

**Undo.** `snapshot` uses `structuredClone` (`history.cloneProject`). `pushHistory` replaces the previous top entry with a wrapper whose project shares every unchanged subtree (array items matched by id, equal pixel arrays reused) with the new top (`shareUnchanged`), so a stroke costs roughly one cel instead of the whole project; the newest entry keeps its identity (motion modes compare it). `historyProject` clones shared entries when restored, so later mutations cannot reach other entries. The stack keeps at most 40 entries and about 12 M array values, dropping the oldest first. `remember` skips steps whose project is unchanged (`sameValue`).

**Rendering and caches.** Pointer moves update the drawing state and request one `requestAnimationFrame` render (`renderSoon`/`flushRender`); `renderAll` cancels a pending one. The canvas paints checkerboard, onion ghosts (cached per frame object, see `editor/onion.js`) and artwork into 1:1 offscreen layers with `ImageData` and scales them with `drawImage` (smoothing off) instead of one `fillRect` per pixel. Thumbnails use `spriteImage` (content-keyed LRU of 32) and cached palette words. Domain caches: `artwork.partPixels` (frozen pixel arrays per part), `geometry.instanceImage` (LRU bounded by area, keyed by part image and pose) and the objects panel's row thumbnails (keyed by the row's operations; reset when parts or palette change). `npm run bench` (Node) and `scripts/profile-browser.mjs` (Playwright, `?perf` hook) measure these paths on the stress projects from `scripts/stress-project.mjs`.

## Build and runtime

`public/` is copied to `dist/`, then `src/` to `dist/src/`. The local service serves only that build directory and rejects paths escaping it. `npm start` builds automatically. `npm run dev` watches browser inputs and rebuilds them in order; Node's watcher restarts the service for server changes. The browser is refreshed manually.

Do not edit generated files. Source files contain no credentials. No remote repository, hosted Site, publication, or deployment is configured by this local setup.

**Image clean-up (`domain/pixelize.js`).** `detectGrid` builds column and row edge-energy profiles and scores candidate periods (2–64 px, 0.05/0.1 steps, then a ±0.1 fine search) by the normalised Fourier magnitude at 1/period; divisors of the true period score equally, so the largest period within 85% of the best wins. It snaps to an integer only when total drift stays under 15% of a cell; the phase gives the offset. `sampleGrid` takes the per-channel median of each cell's inner half (transparent when most of it is). `mergeSimilarColors` folds shades within a Manhattan distance of 28 into the most common one, `removeBackground` flood-fills from the borders (dominant border colour, tolerance 80), and `trimRgba` crops. `averageDownscale` is the photo path. `editor/app.js` `importPng` drives the dialog; palette reduction reuses `paletteFromRgba`.
